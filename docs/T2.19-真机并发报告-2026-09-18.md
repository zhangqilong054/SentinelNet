## 三、关于判据 4 的脚本 bug（如实记录）

首轮判定输出 `🔴 4. 真实抓包生效: capture 运行采样 0/40`，**为脚本误报**：

- 脚本用了不存在的字段 `t.get("running")` 判断任务运行状态，而 `/api/tasks` 的真实契约字段是 `status`（`"running"` / `"idle"`，真相源 `runtime/tasks.py::status_all`）；
- 抓包生效的三条原始数据均在：① `packet_count` 从 43 单调增长到 135,235（直至 591s 仍在涨 → capture 线程全程存活）；② qps 峰值 1,272 / dns 峰值 40（包被解析、协议统计在更新）；③ 非 `LIVE-` 标记告警 11 条（抓包 → 队列 → 检测/攻击 → 写库整条链路产出）；
- 脚本字段 bug 已修正（`status == "running"`），修正版未再重跑 600s（判据各组成项均有本轮原始数据支撑，重跑不产生新信息量）——此判定方式与「期望值来自外部真相源」审计原则一致。
