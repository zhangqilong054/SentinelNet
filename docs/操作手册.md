## 1. 系统概述

SentinelNet 是基于 Python 的实时网络入侵检测平台，核心能力：

- **流量采集**：Scapy/Npcap 实时抓包，支持基础特征和 18 维增强特征提取
- **双引擎检测**：规则检测（实时）+ ML 检测（周期聚合），三级告警（高危/中危/低危）
- **模型训练**：RF/XGBoost/LightGBM/MLP/LR 五种算法，含交叉验证和算法对比
- **Web 监控**：FastAPI 实时仪表盘（Vue 3 前端），含 QPS 趋势图、告警日志、攻击类型饼图
- **攻击模拟**：SYN Flood/端口扫描/UDP Flood 模拟，支持 pcap 文件生成

### 系统架构

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────────┐
│  流量采集    │───▶│  特征提取     │───▶│  双引擎检测   │───▶│  Web 监控面板     │
│  Scapy/Npcap│    │  18 维特征    │    │  规则 + ML    │    │  FastAPI 实时仪表盘 │
│  TLS 解析   │    │  JA3 指纹     │    │  告警分级     │    │  API + 认证      │
└─────────────┘    └──────────────┘    └──────────────────┘    └──────────────────┘
                          │                     │                      │
                          ▼                     ▼                      ▼
                   ┌──────────────┐    ┌──────────────┐      ┌──────────────┐
                   │  模型训练     │    │  日志持久化   │      │  Docker 部署  │
                   │  RF/XGB/LGBM │    │  JSON Lines  │      │  一键启动     │
                   │  算法对比     │    │  Rotating    │      │  健康检查     │
                   └──────────────┘    └──────────────┘      └──────────────┘
```

## 3. 命令行操作

启动 Web 面板：

```bash
python main.py app     # http://localhost:5000
```

> **首次启动引导**：项目根目录没有 `.env` 且未设置 `CAMPUS_IDS_SECRET_KEY` 时，
> 启动会**自动生成 `.env`**（含随机生成的强密钥与 `CAMPUS_IDS_FRONTEND=new`）并正常启动，
> 无需任何手动配置。生成的 `.env` 幂等——已存在则不会改写。
> 启动后访问 http://localhost:5000 即 Vue3 SPA 交互界面（2026-09-19 起为默认；
> 如需旧的 Jinja2 只读壳做 API 冒烟，在 `.env` 设 `CAMPUS_IDS_FRONTEND=legacy`）。

### 3.1 管理员密码重置

```bash
python main.py reset-password                    # 随机生成新密码（推荐）
python main.py reset-password --user admin --password YourNewPwd123
```

- 用户不存在时会直接创建；明文密码仅在 stdout 打印一次，不落日志；
- **首次部署 / 密码遗失时都走本命令**，没有其他默认密码。

所有功能均通过 Web 面板操作，无需额外命令行参数：

| 功能 | Web 面板入口（Vue3 SPA） |
|------|-------------|
| 基础/增强抓包 | 任务中心 → 抓包 / 增强抓包任务 |
| 模型训练 | 系统 → 模型训练（数据集路径 + 轮数，需 confirm） |
| 入侵检测 | 检测引擎常驻运行（规则实时 + ML 周期聚合）；观测页查看实时告警 |
| 一键演示 | 剧本 → demo 剧本一键启动（或任务中心 → 一键演示） |
| 攻击模拟 | 任务中心 → 攻击模拟任务 |
| 一键全流程 | 剧本 → full 剧本一键启动（抓包 → 训练 → 检测） |
| 环境自检 | 系统 → 系统状态 |

> **注意**：旧版 CLI 子命令（capture/ecapture/train/detect/demo/check/auto/menu/attack_sim）已整合到 Web 面板，命令行入口不再支持。

## 4. Web 监控面板

### 4.1 面板页签（Vue3 SPA，默认前端模式）

| 页签 | 核心组件 |
|------|----------|
| **观测** `/observe` | 实时指标卡（窄屏自动 2×2，含活跃告警）+ 流量趋势图 + 最近告警列表（级别过滤；**新告警 3 秒红色高亮渐隐**） |
| **任务中心** `/tasks` | 8 个任务（抓包/增强抓包/检测/ML/攻击模拟/训练/一键全流程/一键演示）的启动/停止与实时进度 |
| **剧本** `/scenarios` | 剧本中心：demo / full / attack 剧本卡片与一键启动 |
| **配置** `/config` | 阈值配置表单（DDoS/端口扫描/SYN/UDP 等，热更新生效） |
| **系统** `/system` | 模型管理（指标标签化展示 + best 模型「当前最佳」徽标；训练终态自动停轮询）+ 系统状态（**运行时间整秒逐秒刷新**）+ 环境自检 |

> **界面交互细节（2026-09-19 UI 优化轮）**：
> - **暗色模式**：侧栏底部「外观」开关，选择持久化在 localStorage；
> - **SSE 状态**：侧栏底部状态标签，未连接/重连中时**点击可立即重连**；
> - **运行时间**：本地每秒推算 + 每 30s 向 `/api/health` 校准，避免逐秒打接口；
> - **加载态**：系统状态卡加载中显示骨架屏，与「无法获取系统状态」区分；
> - 页签切换带淡入过渡。

> **载荷检测边界说明**：载荷检测（SQL 注入/XSS）为**手工送检能力**，仅通过 `POST /api/payload/check` 接口提交待检文本。实时抓包链路不做 HTTP 载荷重组，因此不会在实时检测中自动触发载荷告警。如需实时检测 HTTP 载荷，需另行部署 HTTP 层检测代理。

> **legacy 页签对照**（`CAMPUS_IDS_FRONTEND=legacy` 的 Jinja2 只读壳，无操作按钮，仅 API 冒烟用）：总览 / 加密流量 / 双引擎 / 告警 / 载荷检测 / 控制。

### 4.2 双引擎检测

| 检测引擎 | 告警等级 |
|----------|----------|
| 规则 + ML 同时触发 | **高危** |
| 仅 ML 触发 | **中危** |
| 仅规则触发 | **低危** |

### 4.3 实时抓包

「任务中心」页签启动"基础抓包/增强抓包"任务（需 Npcap/Root）；停止后恢复模拟数据回退。

### 5.3 关键接口详情

> **⚠️ 写操作（POST/PUT/DELETE）在默认配置下需要 CSRF Token**：会话模式下 CSRF 强制生效。
> 仅带 `Content-Type` 头**不能**绕过校验，缺 token 的写操作一律返回 `403`。
>
> ```bash
> # 默认配置：先取 CSRF 令牌，再调用
> TOKEN=$(curl -s http://localhost:5000/api/csrf-token | python -c "import sys,json;print(json.load(sys.stdin)['csrf_token'])")
> curl -X POST http://localhost:5000/api/tasks/capture/start \
>   -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json"
>
> # Bearer 模式（写操作豁免 CSRF）：直接带 Authorization
> curl -X POST http://localhost:5000/api/tasks/capture/start \
>   -H "Authorization: Bearer $CAMPUS_IDS_API_TOKEN" \
>   -H "Content-Type: application/json"
> ```
>
> 下文示例为便于阅读省略了 token 头，实际调用请按上式补齐。

#### POST /api/tasks/{name}/start

统一任务启动端点，替代旧的多组 start/stop/status 端点：


### 5.4 API 认证

系统支持两种认证方式，默认启用（`CAMPUS_IDS_AUTH_ENABLED=1`），通过环境变量控制：

#### 会话认证

```bash
export CAMPUS_IDS_AUTH_ENABLED=1
export CAMPUS_IDS_SECRET_KEY=your-secret-key
```

启用后，所有 API 端点需先登录获取会话。管理员账户：`admin`，密码由
`python main.py reset-password` 设置/重置（**不存在固定默认密码**）。

> **⚠️ 非 DEBUG 模式下 `CAMPUS_IDS_SECRET_KEY` 不能为默认值**，否则应用拒绝启动。

| 路由 | 方法 | 说明 |
|------|------|------|
| `/login` | GET/POST | 登录页面 |
| `/logout` | POST | 登出 |
| `/change-password` | GET/POST | 修改密码 |

> HTML 页面免认证，仅 API 接口需要认证。

#### API Token 认证

```bash
export CAMPUS_IDS_AUTH_ENABLED=1
export CAMPUS_IDS_API_TOKEN=your-secret-token

# 请求时携带
curl -H "Authorization: Bearer your-secret-token" http://localhost:5000/api/traffic
```

> 两种认证可同时启用，会话认证优先。若 `CAMPUS_IDS_API_TOKEN` 为空，则 API Token 认证自动禁用（无论 `AUTH_ENABLED` 设置为何值）。

#### 关闭认证

```bash
export CAMPUS_IDS_AUTH_ENABLED=0   # 关闭所有认证（仅限开发环境）
```

## 10. 常见问题与排障

### Q1: `ModuleNotFoundError: No module named 'campus_ids'`

可编辑包未安装或 Python 解释器不一致。解决：`pip install -e .`，确认 Python 路径一致。

### Q2: 抓包报错 `Npcap not found`

Windows 未安装 Npcap。下载 [npcap.com](https://npcap.com/)，安装时勾选 **WinPcap API-compatible Mode**。

### Q2.1: 抓包启动成功但流量数据始终为 0（Windows）

scapy 默认网卡常指向非活动适配器（如未插线的以太网口）。在 `.env` 中显式指定活动网卡：

```ini
# scapy 接口名或系统友好名（WLAN / 以太网）均可
CAMPUS_IDS_CAPTURE_IFACE=WLAN
```

查看可用接口名：

```bash
python -c "from scapy.arch.windows import get_windows_if_list; [print(i['name'], i.get('description','')) for i in get_windows_if_list()]"
```

修改后重启服务并重新启动「基础抓包」任务。

### Q3: Docker 中抓包不工作

Docker 容器无法访问宿主机网络接口，默认启用模拟模式。真实抓包请在宿主机运行。

### Q4: 训练时报 `⚠️ 无足够真实数据`

本地 `traffic_data.csv` 不存在或样本不足 100 条。通过 Web 面板「增强抓包」采集数据，或直接使用 CICIDS2017 数据集训练。

### Q5: XGBoost / LightGBM 训练失败

未安装对应包：`pip install xgboost lightgbm`

### Q6: Web 面板无法访问

1. 确认服务已启动  2. 检查端口占用：`netstat -ano | findstr 5000`  3. 更换端口：`set CAMPUS_IDS_WEB_PORT=8080`  4. 若报 `secret_key 为公开默认值`，设置 `CAMPUS_IDS_DEBUG=1` 或配置强密钥

### Q7: 启用认证后 API 返回 401

确认已设置 `CAMPUS_IDS_SECRET_KEY` 环境变量（非 DEBUG 模式下不能为默认值），且已通过 `/login` 页面登录获取会话。密码遗失时执行 `python main.py reset-password` 重置。

> **注意**：认证默认启用（`CAMPUS_IDS_AUTH_ENABLED=1`）。若需关闭认证，设置 `CAMPUS_IDS_AUTH_ENABLED=0`。

### Q8: POST 请求返回 403 Forbidden（CSRF 校验失败）

CSRF 保护要求 POST/PUT/DELETE 请求携带有效 CSRF Token。获取方式：

```bash
TOKEN=$(curl -s http://localhost:5000/api/csrf-token | python -c "import sys,json;print(json.load(sys.stdin)['csrf_token'])")
```

在请求头中携带：`X-CSRFToken: $TOKEN`。Bearer 模式（设置了 `CAMPUS_IDS_API_TOKEN`）下 CSRF 自动豁免。

> **Windows cmd 用户**：`python -c` 内层的单引号在 cmd 下不可用，改用双引号转义写法：
> ```bat
> for /f %i in ('curl -s http://localhost:5000/api/csrf-token ^| python -c "import sys,json;print(json.load(sys.stdin)[^'csrf_token^'])"') do @set TOKEN=%i
> ```
> 或更简单——PowerShell / Git Bash 下按上方原样执行；浏览器操作则无需手动取 token（前端自动携带）。

### Q9: 启动报错 `secret_key 为公开默认值，拒绝启动`

非 DEBUG 模式下，若 `CAMPUS_IDS_SECRET_KEY` 仍为默认值 `change-me-in-production`，应用将拒绝启动。解决方式：

1. **生产环境**：设置强随机密钥 `CAMPUS_IDS_SECRET_KEY=$(python -c "import secrets;print(secrets.token_hex(32))")`
2. **本地开发**：设置 `CAMPUS_IDS_DEBUG=1` 允许不安全默认值（仅限本地！）
3. **全新环境**：项目根无 `.env` 且未设密钥时，启动会自动生成含随机密钥的 `.env`（首次启动引导），正常情况下不会遇到本错误。
