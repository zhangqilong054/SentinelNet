# 冒烟测试清单

> 阶段0冻结基线用，覆盖全部 34 API 端点 + 4 页面路由 + 6 UI 面板关键交互。
> 重写后逐项回归，任何失败均阻断发布。

## ⚠️ 重写期状态注记（2026-09-17 第五轮更新）

本清单描述的是**旧 Flask 应用**的契约。新 FastAPI 应用（`web_new/`）在 T2 收口后已具备页面路由，
但有 **5 处有意的破坏性变更**，逐项回归时按"新应用列"判定：

| 项 | 旧应用 | 新应用 | 性质 |
|---|---|---|---|
| 页面路由 | `GET /`、`GET /login`、`GET /logout`、`GET /change-password` | 同路径**全部保留且可用** | ✅ 无破坏 |
| `GET /logout` | 302 重定向到 `/login` | **405 Method Not Allowed** | ⚠️ **有意收窄** —— 防跨站强制登出；登出改 `POST /logout` |
| API 文档 | `/apidocs/`（flasgger） | **`/docs`**（Swagger UI）/ `/openapi.json` | ⚠️ 路径变更 |
| 配置端点 | `GET,POST /api/config` | `GET,PUT /api/settings` | ⚠️ 方法变更 + 多键字典收窄为单键 + 响应分组化 |
| **SSE 端点**（M4/M5） | `/api/stream/traffic` + `/api/stream/alerts` **两条** | **`GET /api/stream?topics=traffic,alert` 一条**（旧路径 404） | ⚠️ **合并 + 未知 topic 改 400**（详见 §2 下注） |
| `/logout`（旧应用补充） | 仅在 `CAMPUS_IDS_LOGIN_ENABLED=1` 时**注册**，否则 404 | 恒注册 | 📌 基线录制时因该开关默认关闭，页面路由 golden 录到的是 **404**（真实行为，非录制缺陷） |

> 📌 **`GET /logout` → 405 的实际影响**：浏览器地址栏直接访问 `/logout` 不再登出（这是刻意的）。
> 前端登出按钮必须改为发 `POST /logout`（带表单域 `csrf_token`）。
> 若某条既有自动化脚本依赖 `GET /logout` 登出，需同步改为 POST。
>
> 📌 其余口径（端点编号 M/C/A/O 与预期状态码）**保持冻结不变**，
> 仅 `A2 /api/config`、`A3 /api/save`、`A4 /api/cleanup`、`C15 /api/payload/check` 四项的
> **新应用对应路径**见 `tests/contract/mapping.py`（旧 → 新映射的唯一真相源）。

## 1. 页面路由（4 项）

| # | 路由 | 方法 | 预期状态码 | 预期行为 |
|---|------|------|-----------|---------|
| P1 | `/` | GET | 200 | 返回 index.html，含 6 个 tab-pane |
| P2 | `/login` | GET | 200 | 返回登录表单 |
| P3 | `/logout` | **POST** | 302 | 重定向到 /login（⚠️ **`GET /logout` 在新应用返回 405**，防跨站强制登出） |

> **新应用实测**（真实 uvicorn，隔离 `CAMPUS_IDS_DATA_DIR`）：
> `GET /` 200 · `GET /login` 200 · `GET /change-password` 200 · `GET /logout` **405** ·
> `POST /logout` 302 · `POST /login` 400（缺 CSRF）· `/docs` 200 · `/static/css/app.css` 200。
> 页面路由**有意排除在 OpenAPI 之外**（`include_in_schema=False`，避免污染阶段 3 的 TS 类型生成），
> 故**不能用 OpenAPI 断言页面存在性**，必须真发请求（见 `tests/contract/mapping.py` 的 `expect_status`）。

## 2. 观测端点 — bp_monitor（5 项）

| # | 路由 | 方法 | 预期状态码 | 预期行为 |
|---|------|------|-----------|---------|
| M1 | `/api/traffic` | GET | 200 | 返回 `{packets, qps, connections, …}` JSON |
| M2 | `/api/traffic/history` | GET | 200 | 返回 `{history: [{ts, qps, …}]}` JSON |
| M3 | `/api/alerts` | GET | 200 | 返回 `{alerts: […]}` JSON |
| M4 | `/api/stream/traffic` | GET | 200 | SSE 连接，Content-Type: text/event-stream |
| M5 | `/api/stream/alerts` | GET | 200 | SSE 连接，Content-Type: text/event-stream |

> M4/M5 为 SSE 长连接，仅验证握手成功即可，不验证事件内容。
>
> ⚠️ **新应用把 M4/M5 两条连接合并为一条**：`GET /api/stream?topics=traffic,alert`。
> 旧路径 `/api/stream/traffic` 与 `/api/stream/alerts` 在新应用返回 **404**。
> ⚠️ topic 取值是**单数 `alert`**（不是 `alerts`）—— 帧的 `event:` 名 == topic 名，
> 沿用旧应用 `_broadcast_sse("alert"|"traffic", …)` 的对外契约，旧前端 `addEventListener('alert', …)` 无需改动。
> ⚠️ 未知 topic（含尚无生产者的预留位 `tasks` / `detection`）→ **400**，
> 不再像旧实现那样静默回落到默认订阅（那是静默失败：调用方以为订阅成功却收的是别的东西）。
> ⚠️ **`curl` 打这条端点会一直挂着**（无限流），要验证得加 `-m 3` 或 `head -c`；
> 且**不要**用 `TestClient` 打它 —— 会静默挂死整个测试会话（详见 §5.3 R5 落地结果）。

> ⚠️ **A3 / A4 是破坏性端点，逐项回归时必须在副本上做**：
> - **A4 `/api/cleanup`**（新应用 `POST /api/admin/cleanup`）：`days` 是**真实生效**的过期天数
>   （`cutoff = now - timedelta(days=days)`）。**不要**用 `days=9999` 之类的极小值/极大值去"试跑"——
>   那是在真实库上做破坏性写操作。正确做法：把 `sentinelnet.db` 复制到临时目录、
>   用 `CAMPUS_IDS_DATA_DIR` 指向副本，再断言 `days=7` 删掉 30 天前的行、保留刚插入的行。
>   （2026-09-17 曾有一条"用 `days=9999` 测清理是安全的"的口径，**已作废**：该结论建立在
>   "`days` 被忽略"这个缺陷之上，缺陷修复后不再成立。）
> - **A3 `/api/save`**（新应用 `POST /api/admin/export`）：会写 `traffic_data.csv` / `traffic_stats.csv`。
>   同样用隔离 `data_dir` 跑。
>
> ⚠️ **CSRF 拒绝码在新旧应用间不同**：旧应用缺 token 返回 **400**，新应用返回 **403**（`X1` 的 400 只适用于旧应用）。

## 8. 跨切面验证（4 项）

| # | 场景 | 预期 |
|---|------|------|
| X1 | POST 端点不带 CSRF token | 旧应用 **400**；新应用 **403**（带 `Content-Type` 不能绕过；仅 Bearer 模式才有豁免） |
| X2 | 并发启动同一任务 | 第二次返回 400，不创建重复线程 |
| X3 | 停止未运行的任务 | 返回 400，不报错 |

> **新应用实测（`scripts/probe_t2_acceptance.py` §⑨，2026-09-17）**：
> X1 → `无 CSRF 的写操作被拒 = 403`；写端点限流 → `{200: 1, 409: 29, 429: 20}`（429 已出现，限流生效）。
> 📌 新应用 X2/X3 的状态码是 **409（冲突）** 而非 400 —— 见 `tests/contract/mapping.py`。
> 📌 另注：`GET` 端点**未限流**（`default_limits` 声明未对 GET 生效），新应用实测 80× GET 全 200。
