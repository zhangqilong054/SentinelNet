## 二、环境修复：Docker Desktop 本体（此前 daemon 无法启动）

根因链：安装目录缺失两个引擎镜像（`resources/docker-desktop.iso` 765MB、`resources/wsl/docker-wsl-cli.iso` 795MB，**只剩 `.sha256` 校验文件**，疑被磁盘清理工具删除）→ backend 崩溃退出。

修复路径（未重装，精准补文件）：
1. 引导安装器（6.9MB stub）静默装失败（exit 3，`Missing package flag`）；
2. 从 `desktop.docker.com/win/main/amd64/<buildNumber>/` 下载与已装版本完全一致的完整安装包 4.86.0（600MB，build 236216）；
3. 安装器自解包的 `DockerDesktop.d4w` **就是 7z 归档**——抢在安装器自删临时目录前拷出，用安装目录自带 `7zr.exe` 直接解出两个 ISO 放回 `resources/`；
4. SHA256 双双与随附校验文件一致 → daemon 370 秒后就绪（29.7.2）。

## 三、镜像首构抓出的 4 个真实缺陷（全部修复）

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | **Dockerfile `npm ci` 从未跑通过** | ERESOLVE：`openapi-typescript@7` peer 要求 TS `^5.x`，项目用 `typescript ~6.0.2`（与本地开发装依赖时同一冲突） | `npm ci --prefer-offline --legacy-peer-deps`（与本地一致）；根治需升级 openapi-typescript 或降 TS，另列技术债 |
| 2 | **CMD 语法错误——镜像从未启动成功过** | `Error loading ASGI app. Attribute "create_app()" not found`：uvicorn factory 语法不认带括号的 `create_app()` | `create_app()` → `create_app`（`--factory` 标志已在） |
| 3 | **生产密钥无配置路径** | 非 DEBUG 模式被 `_assert_secret_key` 正确拒绝（安全闸门在工作，但 compose 从未提供注入方式） | compose `environment` 增加 `CAMPUS_IDS_SECRET_KEY: ${CAMPUS_IDS_SECRET_KEY:?please-set-...}` 强制注入 |
| 4 | **依赖清单缺 `python-multipart`** | 容器从零装依赖后启动即崩：`Form data requires "python-multipart"`（本地环境碰巧装了 0.0.32，测试全绿掩盖了未声明） | `requirements.txt` + `pyproject.toml` 双份补 `python-multipart>=0.0.20` |
| 5 | **数据卷目录属主 root** | 非 root `appuser` 启动即 `unable to open database file`（`/app/data`、`/app/logs` 属主 root） | `mkdir -p` + `chown` 后再声明 `VOLUME`（卷初始化继承 appuser 属主） |

（表中实为 5 行：#1-#2 使镜像从未构建/启动成功，#3-#5 使启动后必然失败——**即 Docker 路径此前完全不可用**。）

另：新增 `.dockerignore`（排除 data/models/tests/backup/node_modules 等，构建上下文瘦身）。
