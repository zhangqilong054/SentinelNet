# Web 交互化方案 — 让 SentinelNet 成为真正的 Web 应用

> 日期：2026-09-19 · 基线：`179e118`（工作区干净，仅 3 个已删除的旧报告文档）
> 验证方式：真实 uvicorn（隔离 `CAMPUS_IDS_DATA_DIR`）双模式实测，非 TestClient 推断

## 一、诊断结论：为什么"当前 Web 无法交互"

**根因只有一个：交互式前端（Vue3 SPA）已经构建完成并躺在 `frontend/dist/`，但后端默认走 `legacy` 模式，服务的是 T2.17 那套刻意做成"只读壳"的 Jinja2 SSR 页面。**

`.env`（首次启动引导生成）只写入了 `CAMPUS_IDS_SECRET_KEY`，没有 `CAMPUS_IDS_FRONTEND=new`；`Settings.frontend` 默认值为 `"legacy"`。

真实 uvicorn 双模式实测（端口 8897，隔离数据目录）：

| 路径 | 默认（legacy） | `CAMPUS_IDS_FRONTEND=new` |
|---|---|---|
| `GET /` | 200 · **Jinja 只读壳**（无任何可点按钮） | 200 · **SPA**（`id="app"`，Element Plus 交互界面） |
| `GET /tasks` | **404** | 200 · SPA 回退 |
| `GET /login` | 200 · Jinja 登录页 | 200 · SPA 登录页 |
| `GET /logout` | 405（防跨站登出，刻意） | 405（同左） |
| `GET /api/health` | 200 | 200 |

也就是说：**系统 29 个 API 端点、8 个编排任务、SSE 实时流全部就绪，用户却只能看到一张"只能看不能动"的静态壳**——交互能力被默认配置锁在了身后。

## 三、方案分级

### 方案 A：配置级启用（5 分钟，0 代码改动）

`.env` 追加一行后重启：

```ini
CAMPUS_IDS_FRONTEND=new
```

- 效果：上表第二列立即生效，SPA 完整可交互。
- 局限：只解决"这一台机器"的问题——下一个新环境（含 Docker 外裸部署）仍会默认吃到只读壳。

### 方案 B：默认值翻转（推荐，真正的开箱即交互）

把 `runtime/settings.py` 的 `frontend` 默认值从 `legacy` 翻转为 `new`，legacy 降级为显式 opt-in：

| 改动点 | 内容 |
|---|---|
| `settings.py` | `default="new"`；dist 缺失时沿用现有 RuntimeError（提示 `npm run build`，不静默回退） |
| `tests/conftest.py` | import 期 `os.environ.setdefault("CAMPUS_IDS_FRONTEND", "legacy")`，与 `CAMPUS_IDS_DEBUG` 同层——测试套件继续覆盖 legacy 页面路由，不因默认值翻转而崩 |
| `tests/test_first_run.py:61` | 默认值断言 `legacy → new` |
| `.env.example` / README | 注明两模式语义与切换方法 |
| 首次启动引导 `_ensure_env_file` | 生成 `.env` 时写入 `CAMPUS_IDS_FRONTEND=new`（显式留痕，便于用户发现可改） |

风险提示：翻转后，未构建 dist 的裸环境从"静默只读壳"变为"启动报错+构建指引"——这是**把静默失败变成显式失败**，符合本项目一贯原则，但要在 README 里写清。

### 实施中额外抓出并修复的 P0（冷启动串测的真价值）

**首启引导在真实链路上是坏的**（`3be8784` 引入时仅函数级测试）：
`main.py` import 期 → `setup_logging()` → `config.py` 兼容层 `_s = get_settings()` → **Settings 单例在 `_ensure_env_file()` 之前物化**（缓存默认密钥）；引导后写入的 `os.environ` 救不了已缓存的单例 → `create_app()` 仍以默认密钥拒绝启动。
实测：删除 `.env` 冷启动必现 `RuntimeError: secret_key 为公开默认值`。
**修法**：`_ensure_env_file()` 生成 `.env` 后调用 `reset_settings()`；新增回归测试 `test_ensure_env_file_resets_materialized_singleton`。
这是「import 期按值绑定/单例物化时机」教训（本项目已连中多次）的又一变体：**写 env 变量对已物化单例同样无效**。
