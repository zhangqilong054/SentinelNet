## 三、本轮新发现（1 个 P2 级坑）

- **`CAMPUS_IDS_FRONTEND` 写进 `.env` 会被静默忽略**。`.env` 仅由 pydantic-settings 读入 `Settings` 模型（`settings.py:26`），而 FRONTEND 是 `app.py:439` 直接 `os.environ.get` 读取——pydantic 不会把 `.env` 注入回 `os.environ`，因此只有**真实环境变量**（或 docker compose environment）对 FRONTEND 生效。
  - **影响**：操作手册 §6 声称"支持 .env 文件"，用户在 `.env` 里配 `CAMPUS_IDS_FRONTEND=new` 不生效且无任何提示。
  - **建议**：并入 U1 启动引导一并处理——将 FRONTEND 收编为 Settings 字段，或引导生成 `.env` 时同步 export/文档标注。
- 环境变量双向核对（按 `Settings.model_fields` 别名口径）：代码可接收 38 个 vs `.env.example` 声明 27 个；**无"文档声明但代码不认"**（FRONTEND 见上，经 os.environ 直读确认有效）；12 个代码已认但 `.env.example` 未列的变量（多为新名别名，操作手册 §6 已有记载）——文档补全项，P3。
